# Reversible native maintenance handoff

`prim migration handoff prepare|apply|rollback|status` is a legacy Prim coordinator. It replaces explicitly reviewed integration settings with bytes generated by a hash-pinned native CLI. It does not import credentials, migrate journals, delete legacy data, start either runtime, or resume legacy capture.

This is an operator-supervised maintenance procedure. It is not an unattended atomic transfer between every historical client. Install the patched legacy release, close every old editor/agent session and cached hook process, and keep the native UI/sessions closed with no concurrent Start until the transaction finishes. The legacy pause fences cooperating patched writers; it cannot prove that older cached binaries or direct API clients stopped. Enumerate every repository and custom host configuration root served by the selected global hooks.

## Procedure

1. Close legacy sessions; run `prim migration pause`, record its ID, then `prim migration drain --id ID`. `prim migration ready --id ID` must report complete inventory, zero active leases, and every legacy queue partition empty. Foreign, unknown, quarantined, or pending data blocks handoff.
2. Authenticate and enroll the native app separately while its host integrations are disconnected. The qualified forward scope requires v3 machine authority with an explicit authorized user, organization, machine and client. Actorless v1 sign-in is held. Do not copy any old token into the native profile or transaction.
3. Write a private (0600) reviewed specification, including exact old hook entries/blocks, expected protected authority, and independently reviewed executable SHA-256 hashes. Prepare runs protected `auth.verify`, compares `auth.status`, rejects native pending/quarantined data, and obtains a settled Quit acknowledgement. It never calls Start.
4. Run `prim migration handoff prepare --spec /absolute/spec.json --transaction /absolute/new-directory`. The directory must be outside declared capture repositories. Review its private snapshots locally. Preparation changes no installed integration files. The resulting reservation blocks legacy resume until a successful rollback.
5. Run `prim migration handoff apply --transaction /absolute/directory`. The same legacy pause and empty queues, pinned artifacts/profile/authority, native stopped epoch, and exact inventory must still hold. Prepared authentication evidence expires after five minutes. Every changed file is accepted only if it matches its recorded preimage or postimage, including mode.
6. After successful apply, explicitly start native operation only when ready. Legacy remains paused and its credentials/journals remain intact. Do not run legacy setup/install/uninstall or edit the scoped host/Git settings during the handoff.
7. To return to legacy, end native sessions, drain native pending/quarantined work, and run `prim migration handoff rollback --transaction /absolute/directory`. Rollback obtains settled Quit again, checks the locally held expected authority/profile and zero queues, and can record a new runtime epoch after a restart. It does not require successful network credential verification merely to restore legacy after revocation. It restores exact bytes/modes and receipt absence, persists the terminal record, then releases the reservation. Finally run `prim migration resume --id ID` explicitly. Rollback never resumes legacy itself.

`status` reports transaction metadata and requirements, not an independently measured live pause. Preserve the transaction directory through the rollback retention period. It contains complete config snapshots that may contain sensitive environment/settings values: do not attach it to issue reports, releases, CI artifacts, or chat. Command output includes paths/state only, never snapshot bodies or token values.

Use actual entries, not the illustrative launcher above. Each reviewed entry must be present exactly once. A separate `removeStatusLine` object authorizes replacing the exact legacy footer. Unknown remaining Prim commands are refused. Known user/default/custom directories and each declared project's Claude/Codex/Cursor configs are inventoried; Hermes supports user scope. Cursor's user footer companion is included, including newly created native footer configuration. Existing native ownership receipts are refused during fresh preparation. Custom unrelated settings and YAML nodes are retained.

Git targets use `{kind:"git", path, removeBlock}` with the exact legacy `# >>> prim EVENT hook >>>` through `# <<< prim EVENT hook <<<` block. Local/composable hooks, including declared repositories’ Husky source hooks, retain unrelated shell code. Existing target parent directories must exist; missing configuration parents are held for explicit preparation. A whole owned global hook additionally requires `global:true` and `reviewedFileSha256`; its path must be the effective global hooksPath and its entire source must match a known legacy-owned template. Custom tails are refused. Existing global hooksPath is never changed. Known legacy passthrough stubs remain guarded; native global chaining replaces managed global hooks and prevents duplicate native invocation in repository hooks. Clear `GIT_*` overrides before inventory. Git errors, unreadable origins, unexpected hook paths and symlinks fail closed.

Legacy `.prim/redaction.json` is retained. Any discovered legacy custom rules require a separately reviewed `.prim/redaction-go.json`; conversion is never inferred. For every native config, provide `{path,sha256,reviewedForGoRE2:true,probe,expected}`. The pinned native redaction worker must produce the exact expected synthetic probe. Directory/config inventory is checked again before mutation. Bounds are 64 declared repositories, 256 targets, 128 reviewed rule files, 2,000 scanned capture directories and 25,000 directory entries. Git metadata, dependencies and symlinked directories are outside capture-scope discovery; separately declare real capture roots instead of assuming they were traversed.

## Interruption and recovery

A durable private reservation survives process death and prevents supported legacy resume. The coordinator holds the maintenance lock during config changes and compatible native per-path locks. Durable intent precedes the first write; each replacement/removal and transaction progress update is flushed. Re-run apply to finish an interrupted forward operation, or rollback to restore preimages. Files matching neither saved image are retained and the transaction stays held. Resolve outside edits explicitly; never blindly copy a backup over them.

There are conservative manual-repair boundaries: a crash between creating a per-path lock directory and persisting its ownership receipt, or while persisting that receipt, can leave an ambiguous lock. Automatic recovery deliberately refuses to remove such a lock. Inspect the private transaction and verify no live owner before any operator repair. Crashes after owned lock receipts and between target writes are automatically recoverable. Filesystem corruption, missing/corrupt snapshots, or an unreadable reservation also stay held. The multi-file change is recoverable under maintenance, not one filesystem-atomic rename.

Native Quit does not prevent a separate operator from pressing Start. The closed-session/no-concurrent-Start prerequisite remains mandatory; stopped state and zero queues are rechecked at every write boundary. A later unsupported Start or outside filesystem edit can make recovery refuse. These explicit limitations are not release-gate acceptance for unattended cutover, real production credentials, newer macOS versions, signing/notarization, or rollback to an older native binary.

## Repeatable qualification

Build the legacy CLI, then run `node scripts/check-migration-handoff-e2e.mjs --native-cli /absolute/native/prim --native-runtime /absolute/native/primitive-runtime --report /absolute/report.json`. The process suite records both native executable hashes and drives the shipped legacy command against private synthetic host settings, an owned synthetic Unix authority fixture, and the real native installers/RPC client. It covers byte restoration, every target/receipt write interruption, reservation retention, late outside edits, identity/queue/quit refusals, and no secret/config snippets in command output. Its synthetic authority does not qualify real sign-in or Keychain behavior; a separate actual-native-owner rehearsal supplies that compatibility evidence. Existing `node scripts/check-migration-maintenance.mjs` and `--staged` runs cover the shared producer fence in ordinary and immutable staged bundles.
